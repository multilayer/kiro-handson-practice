# 技術的な前提

## 作るものの形

- ブラウザ（Edge または Chrome）でダブルクリックして開く **HTML ファイル1つ**（`summary.html`）
- HTML・CSS・JavaScript を1つのファイルにまとめる
- 外部のライブラリや CDN は使わない（ネットワークの制限で読み込めないことがあるため）
- CSV はファイル選択で読み込む。文字コードは UTF-8 と Shift_JIS の両方に対応する

## 使わないもの

- サーバー、データベース、クラウド（AWS などへのデプロイはしない）
- Node.js、Python などの追加のソフト（利用者の PC には入っていない前提。インストールもしない）
- パッケージのインストール（npm install、pip install など）

## テストの考え方

- 自動テストを実行する仕組みはない。**テストのコマンドは使わない**
- 代わりに、受け入れ条件ごとの「手動確認チェックリスト」を Markdown で作る
- 人が `summary.html` を開き、`変更依頼一覧_サンプル.csv` を読み込んで、チェックリストどおりに確認する

## 守ること

- やりとり・作る文書・画面の文言は **すべて日本語**
- 個人情報・顧客情報は扱わない。それらしき情報が出てきたら作業を止めて知らせる
- 資料に書かれていないことを推測で補わない。補う場合は「推測」と明記する
- git の操作はコミットまで。push はしない
