# STEP 2 GitHub を見て、Kiro に取り込む（45分）

## この回の目的

- GitHub が「変更履歴が全部残る共有フォルダ」だと知る
- GitHub のリポジトリを自分の PC に取り込み（クローン）、Kiro で開けるようにする
- Kiro に頼んで、自分用のブランチを作る

> GitHub の画面は **見て回るだけ** です。ファイルの保存や送信は、この先すべて Kiro に頼んで行います。
> この回の操作は **最初の1回だけ** 必要なものが多いので、焦らず進めましょう。

## まず言葉を4つだけ覚える

| GitHub の言葉 | ふだんの言葉で言うと |
|---|---|
| リポジトリ | 変更履歴が全部残るフォルダ（このハンズオンなら、自分のアカウントにコピーした `kiro-handson-practice`） |
| コミット | 保存。「いつ・誰が・何を・なぜ」変えたかが記録される |
| ブランチ | 作業用のコピー。本体（main）を汚さずに試せる |
| プルリクエスト | 「この変更を本体に取り込んでください」というレビュー依頼（STEP 6 で使います） |

ほかの言葉は [用語集](glossary.md) にまとめています。

## 準備するもの

- STEP 1 で Kiro と GitHub にログインできていること
- 自分のリポジトリの URL（`https://github.com/＜自分のユーザー名＞/kiro-handson-practice`）

---

## 手順

### 1. ブラウザでリポジトリを見て回る（10分）

1. ブラウザで自分のリポジトリ（`https://github.com/＜自分のユーザー名＞/kiro-handson-practice`）を開く
2. ファイル一覧から `materials` → `業務説明_システム変更依頼の流れ.md` を押して中身を読む
   - `.md` は **Markdown（マークダウン）** という書き方のファイルです。`#` が見出し、`-` が箇条書きになります
3. 本文のすぐ上、**左端** にある **Preview / Code** の切り替えを押して、表示が変わることを確認する
   - **Preview**（最初に選ばれている）：見出しや箇条書きが整った表示
   - **Code**：元のテキスト。`#` や `-` がそのまま見える
4. リポジトリのトップに戻り、ファイル一覧の上にある **「○○ commits」**（時計のアイコン）を押す
5. コミットを1つ押すと、そのとき **どの行が追加（緑）・削除（赤）されたか** が見えます

> ここが、フォルダに置いたファイルを上書きしていくやり方との一番の違いです。誰がいつ何を変えたかが、全部残ります。
> コピーしたばかりなので、今は公開元から引き継いだコミットが1つだけかもしれません。STEP 4 以降、自分のコミットが増えていきます。

### 2. 作業用のフォルダを確かめる（5分）

1. エクスプローラーのアドレス欄に `%USERPROFILE%` と入力して Enter（自分のユーザーフォルダ `C:\Users\＜自分＞` が開きます）
2. STEP 0 で作った `kiro` フォルダ（`C:\Users\＜自分＞\kiro`）があることを確かめる。なければ、ここに作る
   - クラウド同期のサービスを使っている人は、その同期の対象になっているフォルダの中には作らないでください。同期と Git がぶつかって、ファイルが壊れたり重複したりすることがあります

### 3. Kiro でクローンする（15分）

1. ブラウザの自分のリポジトリの画面で、緑色の **「Code」** ボタンを押し、**「HTTPS」** タブの URL の横のコピーボタンを押す
2. Kiro IDE を開き、キーボードで **`Ctrl` + `Shift` + `P`** を押す
   - 画面上部に入力欄（コマンドパレット）が出ます
3. `Git: Clone` と入力し、出てきた **「Git: Clone」** を選ぶ
   - ようこそ画面に **「Clone Repository」** があれば、そちらを押しても同じです
4. コピーした URL を貼り付けて Enter
5. 保存先を聞かれるので、手順2で作った `kiro` フォルダ（`C:\Users\＜自分＞\kiro`）を選ぶ
6. **初回だけ**、GitHub へのサインインを求められます
   - ブラウザが開いたら、自分の GitHub アカウントでサインインし、**Authorize（許可）** を押す
   - 「Git Credential Manager」という画面が出た場合も、同じく **Sign in with your browser（ブラウザでサインイン）** を選ぶ
   - Private のリポジトリは、サインインしないとクローンできません。Public にした人は、サインインを聞かれずに終わることもあります（その場合は STEP 4 の初めてのプッシュで聞かれます）
7. 取り込みが終わると「開きますか？」と聞かれるので **「Open（開く）」** を押す
8. 「このフォルダの作成者を信頼しますか？」と聞かれたら、**このハンズオンのリポジトリに限り** 信頼する（Trust）を選ぶ

左側のファイル一覧に `README.md` や `docs` フォルダが見えれば成功です。

### 4. Kiro に頼んで、自分用のブランチを作る（10分）

これから先の作業は、すべて自分用のブランチで行います。ブランチは Kiro に作ってもらいましょう。

1. キーボードで **`Ctrl` + `L`** を押し、右側にチャット欄を開く（画面右上のチャットの切り替えボタンでも開けます）
2. 次の文を、`taro` を自分の名前（ローマ字）に変えて送る

   ```
   practice/taro という名前のブランチを作って、そのブランチに切り替えてください。
   ```

3. Kiro がコマンド（`git switch -c practice/taro` のような1行）を実行しようとして、**許可を求める表示** が出ます
   - 表示されたコマンドに、自分のブランチ名が入っていることを確かめてから許可する
   - 意味の分からないコマンドや、`main` を消す・上書きするようなコマンドなら、**許可せずに止まって**、「このコマンドは何をするものですか」とチャットで聞く
4. 画面左下の表示が `main` から `practice/taro` に変わったことを確認する

> ブランチは「作業用のコピー」です。ここで何をしても、main（正式版）は変わりません。
> Kiro はファイルの書き換えやコマンドの実行の前に、許可を求めてきます。**表示された内容を読んでから許可する** 習慣を、ここで身につけましょう。

### 5. ふりかえり（5分）

- ファイルをメールに添付して送り合い、各自が直して返すやり方と比べて、何が違いそうか（メモに書き出す）
- 「main を直接変えず、ブランチで作業する」ことの良さは何か

## できたかチェック

- [ ] Markdown ファイルの Preview と Code を切り替えた
- [ ] コミット履歴を開いて、追加・削除の行を見た
- [ ] Kiro の左側に、このリポジトリのファイル一覧が見えている
- [ ] 画面左下のブランチ名が `practice/自分の名前` になっている

## 困ったとき

- 「git が見つかりません」と出る → Git が入っていません。[STEP 0](00-environment.md) の「2. Git をインストールする」に戻る
- サインインのブラウザが開かない、何度も聞かれる → [困ったとき集](troubleshooting.md) の「GitHub にサインインできない」
- 間違ったフォルダにクローンした → Kiro を閉じ、エクスプローラーでそのフォルダごと削除して、手順3からやり直してよい（GitHub 側には影響しません）
- 公開元のリポジトリをクローンしてしまった（画面に `＜自分のユーザー名＞` ではない名前が出ていた）→ 同じくフォルダごと削除して、自分のリポジトリの URL でやり直す。公開元にはプッシュできません
- Kiro がブランチを作ってくれない、許可の表示が出ない → 画面左下の `main` を押し、**「Create new branch...」** を選んで `practice/自分の名前` と入力しても同じです

## 次回からの開き方

Kiro を起動 → **「File」→「Open Folder...」** → `C:\Users\＜自分＞\kiro\kiro-handson-practice` を選ぶ。
開いたら、まずチャットで「最新の状態を取り込んで（pull して）」と頼み、最新にそろえる習慣をつけましょう。
