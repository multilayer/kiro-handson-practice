# 困ったとき集

まずは **あわてずに手を止める** こと。プッシュしていない変更は自分の PC の中だけのものなので、GitHub のリポジトリが壊れることはありません。

> ここにない症状のときは、Kiro のチャットに「STEP ○ の手順 ○ で、次のメッセージが出ました」と、画面のメッセージを貼って聞いてみてください（**個人情報・顧客情報が写っていないことを確認してから**）。

---

## ログイン・サインイン

### Kiro にログインできない
- サインインの方法（GitHub・Google・AWS Builder ID）が、前回と同じか確認する。方法が違うと、別のアカウントとして扱われます
- **Your organization** を選んでいないか確認する（組織でまとめて用意した Kiro 用です）
- ブラウザが開かない場合：Kiro に表示されている URL をコピーし、ブラウザに貼り付けて開く
- ブラウザで許可したのに Kiro に戻らない場合：Kiro を再起動して、もう一度サインインする

### GitHub にサインインできない / 何度も聞かれる
- ブラウザで自分の GitHub アカウントに先にサインインしてから、もう一度 Kiro で操作する
- 「Git Credential Manager」の画面では **ブラウザでサインイン（Sign in with your browser）** を選ぶ
- 別の GitHub アカウントでサインインしてしまった場合：Windows の「資格情報マネージャー」→「Windows 資格情報」で `git:https://github.com` を削除し、もう一度操作して正しいアカウントでサインインする

## Kiro のチャット

### チャットが反応しない
1. チャット欄上部の「+」で新しいセッションを開いて、もう一度送る
2. Kiro IDE を再起動する
3. クレジットを使い切っていないか、Kiro のアカウントの表示で確認する

### 英語で答えが返ってくる
- 「日本語で答えてください」と付け足す
- `.kiro/steering/rules.md` が残っているか確認する（消してしまった場合は Pull で戻る）

### 許可を求める表示が出て、何をするのか分からない
- 許可せずに「これは何をしようとしていますか」とチャットで聞く
- 分からないままは許可しない

### Kiro が勝手に関係ないファイルを変えた
- その依頼のすぐ上にあるチェックポイントの **「Restore」** を押して、依頼を送る前に戻す
- もっと前に戻したいときは、チャット履歴をさかのぼって、前のチェックポイントの **「Restore」** を押す

### スキルが一覧に出ない・使われない
- `SKILL.md` の `name` とフォルダ名が同じか確認する
- `description` に「〜を頼まれたときに使う」と書いてあるか確認する

### MCP サーバーにつながらない
- `mcp.json` の `{ }` や `,` が崩れていないか確認する
- Kiro パネルの Output タブで「Kiro - MCP Logs」を見る
- 「N servers hidden」と出たら、組織の管理者が許可していないサーバーです。個人のアカウントでサインインしているか確認する

## STEP 10（AI-DLC ワークフロー）

### `aidlc` が見つからない
- インストールの後、PowerShell を開き直す
- Kiro のターミナルや Kiro からの実行で見つからないときは、**Kiro を完全に終了して起動し直す**（Reload Window では直らない）

### インストールで「スクリプトの実行が無効」と出る
- PC の設定で PowerShell スクリプトが止められています
- その PowerShell の窓の中だけ、スクリプトの実行を許可してからインストールをやり直す。窓を閉じると元の設定に戻ります

  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  ```

### エージェントの選択に aidlc が出ない
- まず一覧を **下にスクロール** する。aidlc は上の BUILT-IN ではなく、下の **WORKSPACE** の見出しの下に出ます
- それでもなければ、フォルダを信頼していません。画面上部の Restricted Mode の帯 → **Manage**（日本語表示では「管理」）→ **Trust**（「信頼する」）を押し、`Ctrl`+`Shift`+`P` → **Developer: Reload Window**（「開発者: ウィンドウの再読み込み」）
- AI-DLC のインストール中に Kiro を開いていた場合は、Kiro を完全に終了して起動し直す

### コマンドの実行許可を何度も聞かれる
- チャットのエージェントが **Default** のままです。新しいチャットを開いたら、毎回 **aidlc** を選び直す

### 承認しても先に進まない
- 選択肢の **番号** を入力して Enter しているか確認する
- `/aidlc --doctor` を送り、警告が出ていれば確認する（フォルダの信頼や Kiro の Workflows 機能が原因のことが多い）

### 段階が多すぎる・終わらない
- `/aidlc --status` で型（scope）を確認する。`poc` 以外になっていたら、`/aidlc park` で止め、STEP 10 の手順1から別の名前の作業フォルダを作ってやり直す
- 時間切れのときは `/aidlc park` で止め、次回 `/aidlc --resume` で再開する

## Git・GitHub

### 今どのブランチにいるか分からない
- 画面左下に表示されているのが今のブランチです。`main` になっていたら、押して `practice/自分の名前` を選ぶ（チャットで「今いるブランチを教えて」と聞いてもよい）

### main のまま作業してしまった（コミット前）
1. チャットで「practice/自分の名前 のブランチに切り替えて。まだなければ作って」と頼む（画面左下の `main` を押し、「Create new branch...」で作ってもよい）
2. まだコミットしていない変更は、そのまま新しいブランチに持っていけます

### main のままコミットしてしまった
- **まだプッシュしていなければ、** チャットで次のように頼む

  ```
  main にしてしまったコミットを、practice/自分の名前 のブランチに移してください。main は GitHub の main と同じ状態に戻してください。
  ```

  表示されたコマンドを読み、分からなければ許可せずに「このコマンドは何をするものですか」と聞く
- **プッシュしてしまった場合：** 自分のリポジトリの練習なので、大きな問題はありません。そのまま続けてかまいません。次からは画面左下のブランチ名を確かめる習慣をつけましょう（STEP 0 の「main を守る設定」をしていれば、main へのプッシュは止められます）

### プッシュできない（rejected と出る）
- チャットで「プッシュが rejected になりました。最新を取り込んでから、もう一度プッシュしてください」と頼む

### プッシュで「Permission denied」「403」と出る
- 公開元のリポジトリをクローンしている可能性があります。チャットで「このリポジトリの origin の URL を教えて」と聞く
- URL が `https://github.com/＜自分のユーザー名＞/kiro-handson-practice.git` でなければ、次のように頼む

  ```
  origin の URL を https://github.com/＜自分のユーザー名＞/kiro-handson-practice.git に変えてください。
  ```

- 自分のリポジトリがまだない場合は、[STEP 0](00-environment.md) の「5. このリポジトリを自分の GitHub アカウントにコピーする」を先に行う

### 「競合（Conflict）」と出た
- 同じファイルの同じ場所が、2か所（たとえば GitHub の画面と自分の PC）で別々に変わったときに出ます
- チャットで「競合が起きました。どのファイルのどこが競合しているか、分かりやすく説明してください」と頼み、どちらを残すか決めてから直してもらう

### 自分の PC のフォルダがぐちゃぐちゃになった
- 最終手段として、Kiro を閉じ、PC のフォルダごと削除して、STEP 2 のクローンからやり直してかまいません
- **プッシュ済みのものは GitHub に残っている** ので消えません。プッシュしていない変更だけが消えます
