# STEP 0 始める前の準備（30〜60分）

このハンズオンは、**自分で用意した Kiro** と **自分の GitHub アカウント** で進めます。
この回で、PC・アカウント・ハンズオン用リポジトリをそろえます。終わったら STEP 1 に進んでください。

## この回でそろえるもの

| | もの | 費用 |
|---|---|---|
| 1 | PC（Windows または Mac）と作業フォルダ | ― |
| 2 | Git（PC にインストールするソフト） | 無料 |
| 3 | GitHub のアカウント | 無料 |
| 4 | Kiro IDE（PC にインストールするアプリ）と Kiro のアカウント | 無料プランあり。通しで行うなら有料プランがおすすめ（下の「4. Kiro のプランとクレジット」） |
| 5 | このリポジトリのコピー（自分の GitHub アカウントの中） | 無料 |

## 全体の構成

```
 自分の PC（Kiro IDE ＋ Git ＋ ブラウザ）
   │
   ├─(1) サインイン・AI への依頼 ─▶ Kiro サービス（Google / GitHub / AWS Builder ID でサインイン）
   │
   ├─(2) リポジトリの取得・送信 ──▶ github.com（自分のアカウントにコピーしたハンズオン用リポジトリ）
   │
   ├─(3) STEP 9 のみ ─────────▶ AWS Knowledge MCP サーバー（AWS 公式ドキュメント検索）
   │
   └─(4) STEP 10 のみ ────────▶ github.com（AI-DLC ワークフローのダウンロード）
```

## 1. PC と作業フォルダ

| 項目 | 前提 |
|---|---|
| OS | Windows 10 / 11、または macOS |
| ブラウザ | Edge または Chrome |
| 画面 | ノート PC の画面だけでも可。手順書と Kiro を並べられる外部モニターがあると進めやすい |
| 作業フォルダ | 自分のユーザーフォルダの中の `kiro` フォルダ（下の手順で作ります） |

**作業フォルダを作る（Windows）**

1. エクスプローラーのアドレス欄に `%USERPROFILE%` と入力して Enter（自分のユーザーフォルダ `C:\Users\＜自分＞` が開きます）
2. そこに `kiro` というフォルダを作る（例：`C:\Users\＜自分＞\kiro`）
   - クラウド同期のサービスを使っている人は、その同期の対象になっているフォルダの中には作らないでください。同期と Git がぶつかって、ファイルが壊れたり重複したりすることがあります

> Mac の場合は、ホームフォルダ（Finder で `Cmd` + `Shift` + `H`）に `kiro` フォルダを作ります。iCloud Drive の「デスクトップと書類」をオンにしている場合は、デスクトップや書類の中は避けます。

## 2. Git をインストールする

Kiro から GitHub を使うには、PC に「Git」というソフトが必要です。

**Windows**

1. ブラウザで `https://git-scm.com/` を開き、**Download for Windows** から **Git for Windows** のインストーラーをダウンロードする
2. インストーラーを実行する。途中の選択肢は **すべておすすめ（初期値）のまま** 「Next」で進めてかまいません
   - GitHub へのサインインを手伝う **Git Credential Manager** も一緒に入ります
3. スタートメニューで「PowerShell」と入力して検索し、**Windows PowerShell** を開いて、次を入力して Enter

   ```
   git --version
   ```

4. `git version 2.xx.x` のようにバージョンが出れば OK

**Mac**

1. 「ターミナル」を開き、`git --version` と入力して Enter
2. バージョンが出れば OK。入っていない場合は「コマンドラインデベロッパツール」のインストールを求められるので、**インストール** を押す

> インストールに PC の管理者権限が要る場合は、管理者のアカウントで行ってください。

## 3. GitHub のアカウントを作る

すでに持っている人は、この手順は飛ばしてかまいません。

1. ブラウザで `https://github.com/` を開き、**Sign up** を押す
2. メールアドレス・パスワード・ユーザー名を入力し、画面の案内に沿ってアカウントを作る
3. 届いたメールで、メールアドレスの確認を済ませる
4. **2要素認証（2FA）** の設定を求められたら、画面の案内に沿って設定する（スマートフォンの認証アプリなどを使います）

> 無料プラン（GitHub Free）で、このハンズオンはすべてできます。

## 4. Kiro をインストールしてアカウントを作る

### Kiro IDE をインストールする

1. ブラウザで `https://kiro.dev/` を開き、**Download** から自分の OS 用のインストーラーをダウンロードする
2. インストーラーを実行し、画面の案内に沿ってインストールする
3. Kiro IDE が起動することを確認する（サインインは STEP 1 で行います）

### Kiro のプランとクレジット

Kiro では、AI に頼んだ量に応じて **クレジット** を使います。プランごとに、毎月使えるクレジットが決まっています。

| プラン | 月額 | 月のクレジット | このハンズオンでの目安 |
|---|---|---|---|
| Free | 無料 | 50 | STEP 1〜3 くらいまでのお試し向き。STEP 6 以降は足りなくなる可能性が高い |
| Pro | 20ドル | 1,000 | **STEP 1〜9 を通して行うならこれがおすすめ** |
| Pro+ 以上 | 40ドル〜 | 2,000〜 | STEP 10 を何度も試したい人向け |

- 上の表は **2026年10月時点** の Kiro 公式の料金ページ（`https://kiro.dev/pricing`）の内容です。変わることがあるので、申し込む前に最新を確認してください
- 無料プランで使えるモデルは限られています。**STEP 10（上級編）は上位のモデル（Claude Opus）を使うため、有料プランが必要** です
- 有料プランは、サインインした後に Kiro の画面やアカウントのページから申し込めます。まずは無料プランで STEP 1 を試し、続けると決めてから申し込んでもかまいません
- 使い切ると翌月まで使えなくなります（有料プランでは、追加のクレジットを買う設定もできます）

## 5. このリポジトリを自分の GitHub アカウントにコピーする

このハンズオンでは、ブランチを作ったり、プルリクエストを出したり、マージしたりします。そのため、**自分が自由に変更できる、自分のアカウントのリポジトリ** が必要です。

1. ブラウザで GitHub にサインインした状態で、このリポジトリのページ（公開元）を開く
2. 画面右上の緑色の **「Use this template」** → **「Create a new repository」** を押す
3. 次のように入力する

   | 項目 | 入力する内容 |
   |---|---|
   | Include all branches | **オフ** のまま |
   | Owner | 自分のユーザー名 |
   | Repository name | **`kiro-handson-practice`**（手順書のフォルダ名と合わせるため、この名前がおすすめ） |
   | Description | 空欄でかまいません |
   | 公開範囲 | **Private**（自分だけが見られる）がおすすめ |

4. **「Create repository」** を押す
5. `https://github.com/＜自分のユーザー名＞/kiro-handson-practice` が開き、この README が表示されれば完了です

> **Private がおすすめな理由：** STEP 4 以降、自分の練習の成果物をこのリポジトリに送ります。サンプルの資料でも、練習の跡は自分だけが見られるほうが気楽です。
> 「Use this template」ボタンが見当たらない場合は、右上の **「Fork」** でもコピーできます（この場合、コピーは公開（Public）になります）。

> これから先、手順書に出てくる「このリポジトリ」「GitHub のリポジトリ」は、**ここで作った自分のコピー** のことです。公開元のリポジトリではありません。

### （任意）main を守る設定

うっかり main を直接変えてしまわないよう、GitHub に「main はプルリクエストでしか変えられない」というルールを設定できます。
**リポジトリを Public にした場合** や、GitHub の有料プランを使っている場合に設定できます（無料プランの Private リポジトリでは設定できないので、飛ばしてかまいません）。

1. 自分のリポジトリの **「Settings」** → 左側の **「Rules」→「Rulesets」** → **「New ruleset」→「New branch ruleset」** を押す
2. 次のように設定して、**「Create」** を押す

   | 項目 | 設定 |
   |---|---|
   | Ruleset Name | `protect-main` |
   | Enforcement status | **Active** |
   | Target branches | **Add target** → **Include default branch** |
   | Restrict deletions | オン |
   | Require a pull request before merging | オン（**Required approvals は 0** のまま。ひとりで進めるので、自分の承認なしでマージできるようにします） |
   | Block force pushes | オン |

## 6. ネットワーク（プロキシがある場合だけ）

自宅のネットワークなど、ふつうにインターネットにつながる環境なら、この項目は気にしなくてかまいません。
プロキシやファイアウォールのあるネットワークでは、次の通信（すべて HTTPS／443番ポート）ができる必要があります。

| 通信先 | 用途 |
|---|---|
| `*.kiro.dev`、`q.us-east-1.amazonaws.com` | Kiro のサインイン・AI の処理・自動更新など（詳しくは Kiro 公式ドキュメント「Firewalls, proxies, and data perimeters」） |
| `github.com`、`*.githubusercontent.com`、`github.githubassets.com` | GitHub の画面、Git のクローン・プル・プッシュ、AI-DLC のダウンロード（STEP 10） |
| `knowledge-mcp.global.api.aws` | AWS Knowledge MCP サーバー（STEP 9） |

- **Kiro IDE：** 「Settings」→「Proxy」で設定する（環境変数 `HTTPS_PROXY` も使われる）
- **Git：** ターミナルで `git config --global http.proxy http://＜プロキシ＞:＜ポート＞` を設定する

## 7. データの扱い

- 練習では **リポジトリの `materials/` にあるハンズオン用のサンプル資料だけ** を使う
- **個人情報・顧客情報は、Kiro のチャットにもリポジトリにも入れない**
- Kiro に送った内容は Kiro のサービス（米国のリージョン）で処理されます。MCP の道具に送った質問は、その道具の提供元に届きます
- 無料プランや個人向けプランでは、送った内容がサービスの改善に使われる設定になっている場合があります。気になる場合は、Kiro の設定（Settings で `telemetry` や `content` を検索）とプライバシーに関する公式ドキュメントを確認してください
