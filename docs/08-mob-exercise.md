# STEP 8 モブ演習（90分）

## この回の目的

- 1つの画面を見ながら、AIと対話して **その場で要件を決める** 進め方を体験する（本来は関係者全員で行うものです。ひとりのときは AI に依頼者役をさせます）
- 「持ち帰って書いて、メールで回して、また集まる」をなくすと何が変わるかを感じる

> これは AWS が提唱する **AI-DLC（AI駆動開発ライフサイクル）** の「モブ・エラボレーション（全員集合で要件を詰める）」の考え方を取り入れた演習です。

## 役割（仲間と集まって行う場合）

| 役割 | 人数 | やること |
|---|---|---|
| **ドライバー** | 1人 | Kiro を操作する。自分の意見は言わず、みんなの決定をそのまま入力する |
| **依頼者役** | 1人 | 業務部門の担当者になりきる。お題の背景を知っていて、質問に答える |
| **ナビゲーター** | 残り全員 | AI の質問への答えを話し合って決め、ドライバーに伝える |
| **タイムキーパー** | 1人（ナビゲーターと兼務） | 各パートの時間を知らせる |

ドライバーは **15分ごとに交代** します。

## ひとりで進める場合（この手順書の基本）

モブ演習は本来、関係者全員で行うものです。ひとりのときは **Kiro に依頼者役をさせ**、自分がドライバーとナビゲーターを兼ねます。セッションを2つ使います。

| セッション | 役 | 使い方 |
|---|---|---|
| セッションA | 要件をまとめる AI | 下の「進め方」の手順2〜4をそのまま行う |
| セッションB | 依頼者役の AI | セッションA の AI の質問のうち、依頼者にしか答えられないものを聞く |

1. ブランチは自分の `practice/自分の名前` のまま、Spec の名前は `mob-自分の名前` にする
2. セッションB を開き、次を送る

   ```
   あなたはこれから、#exercises/step08-モブ演習のお題.md の依頼者役を演じます。
   ファイルの中の「依頼者役用メモ」の設定だけを使って、私の質問に依頼者として短く答えてください。
   聞かれていないことは自分から言わないでください。メモにないことは「分かりません。確認します」と答えてください。
   ファイルは書き換えないでください。
   ```

3. セッションA の質問を1つずつ読み、**まず自分で答えを考える**。依頼者でないと分からないことだけセッションB に聞く
4. 決まった答えをセッションA に入力する。決められないものは「未確定事項」にする
5. 手順4のプルリクエストは、「Files changed」で入るファイルを見直してから、自分でマージする
6. 最後に、お題の「依頼者役用メモ」を開き、未確定事項にすべき項目を未確定にできたか確かめる
7. 完成見本 [examples/mob-requirements-sample/requirements.md](../examples/mob-requirements-sample/requirements.md) と見比べる

> 自分の頭で答えを決めるのが目的です。セッションB に何でも聞いて答えを丸写ししないようにしましょう。

## 準備（仲間と集まって行う場合、進行役）

- 大きなモニターかプロジェクター（オンラインなら画面共有）に、ドライバーの Kiro 画面を映す
- ドライバー用の PC で、ドライバーのリポジトリを開き `mob/日付` というブランチを作っておく（例：`mob/20261120`）
- ドライバーを交代するときは、同じ PC の前に座る人が替わるか、画面共有したまま口頭で指示する（全員が同じリポジトリにプッシュする必要はありません）
- お題：[exercises/step08-モブ演習のお題.md](../exercises/step08-モブ演習のお題.md)

## 進め方

ひとりで進める場合は、上の「ひとりで進める場合」の表のとおり、セッションA でこの手順を行います。「ナビゲーター」「ドライバー」「依頼者役」は、自分とセッションB の AI に読み替えてください。

### 1. お題を共有する（10分）

1. 依頼者役がお題を読み上げる
2. ナビゲーターは、分からない点をメモしておく（まだ質問しない）

### 2. AI にたたき台を作らせる（10分）

ドライバーが Spec を始めます。

1. Kiro パネル（おばけのアイコン）の **SPECS** 欄の **「+」** を押す
2. 画面上部に「Enter your idea to generate requirement, design, and task specs.」という入力欄が開くので、次を貼り付けて **Enter** を押す

   ```
   exercises/step08-モブ演習のお題.md の要望について、要件のたたき台を作ってください。
   Spec の名前は mob-＜日付＞ にしてください。
   たたき台を作ったら、決めなければならないことを、重要な順に質問の形で最大10個挙げてください。
   ```

   - この入力欄では `#` でファイルを選べないので、ファイルの場所（パス）をそのまま書いています
   - ひとりで進める場合は、`mob-＜日付＞` を `mob-自分の名前` に変えます
3. チャットに「Input required」と出たら、**Requirements（要件から）** を選んで **Submit answer** を押す
4. ファイルを書き込む許可を求められたら、許可する

### 3. AI の質問に、その場で答えていく（40分）

ここがこの演習の中心です。

1. AI の質問を上から1つずつ読み上げる
2. ナビゲーターが話し合い、依頼者役に確認しながら **その場で答えを決める**（1問 3分以内が目安）
3. 決まった答えを、ドライバーがそのままチャットに入力する
4. 3〜4問ごとに「ここまでの答えを requirements.md に反映して」と頼み、画面で全員が確認する
5. **その場で決められないものは、無理に決めない。** 「未確定事項（確認先：○○）」として残してもらう

> **ルール：** 「あとで考えます」は禁止。決めるか、「未確定事項」にするかのどちらかです。

### 4. 仕上げとプルリクエスト（15分）

1. 最後に、AI に点検させる

   ```
   requirements.md 全体を見て、受け入れ条件どうしで矛盾しているもの、
   テストで合否を判定できないあいまいな書き方のものがあれば指摘してください。
   ```

2. 指摘を直したら、Kiro に「今の変更を『モブ演習の要件を作成』というメッセージでコミットして、プッシュしてください」と頼む。表示されたコマンドに自分のブランチ名が入っていることを確かめてから許可する
3. ブラウザで自分の GitHub のリポジトリを開き、黄色い帯の **「Compare & pull request」** からプルリクエストを出す（base が自分のリポジトリの `main` であることを確かめる）
4. 「Files changed」で、入るファイルが `.kiro/specs/mob-…/` だけであることを確かめてから、**「Merge pull request」→「Confirm merge」** でマージする
   - 仲間と行う場合は、依頼者役がその場で内容を確認してからマージします

### 5. ふりかえり（15分）

話し合います（ひとりのときは、答えをメモに書き出します）。

- ふだんのやり方なら、今日決めたことを決めるのに何日かかっていたか
- AI の質問の中で、人間だけでは気づかなかった観点はあったか
- 実際の仕事でやるとしたら、誰に集まってもらう必要があるか（業務部門？ 開発会社？）

- [ ] ドライバーかナビゲーターを経験した（ひとりのときは両方）
- [ ] AI の質問に、その場で答えを決めた
- [ ] 決められないことを「未確定事項」として残した
- [ ] requirements.md がプルリクエスト経由で main に入った
