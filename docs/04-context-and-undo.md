# STEP 4 資料の渡し方と、やり直し方（60分）

## この回の目的

- `#` を使い分けて、ファイル・フォルダ・リポジトリ全体を Kiro に渡せるようになる
- **監督モード（Supervised）** で、Kiro が直した箇所を1つずつ確かめてから受け入れられるようになる
- 失敗しても **チェックポイントの Restore（復元）** で戻せることを知る
- コミット・プッシュ（保存して GitHub に送る）を Kiro に頼めるようになる

> STEP 3 では「読ませるだけ」でしたが、この回から Kiro にファイルを作らせ、直させます。
> 作るファイルは **`participants/自分の名前/` の中だけ** にします。`materials/` の資料は直しません。

## 準備するもの

- STEP 3 まで終わっていること
- 画面左下が `practice/自分の名前` ブランチになっていること

---

## 手順

### 1. `#` の渡し方を使い分ける（15分）

チャットの入力欄で `#` を入力すると、渡せるものの候補が出ます。STEP 3 で使った **File** のほかに、次の2つを試します。

| 候補 | 渡すもの | 使いどころ |
|---|---|---|
| `#file` | ファイル1つ | 読ませたい資料が決まっているとき（STEP 3 で使用） |
| `#folder` | フォルダの中身まとめて | 関係する資料が1つのフォルダにまとまっているとき |
| `#codebase` | リポジトリ全体から探させる | どのファイルに書いてあるか分からないとき |

新しいセッションを開き、次の2つを順に送ってください。`#` の部分は候補から選びます。

```
#folder materials フォルダの資料をすべて読んで、それぞれ何の資料かを1行ずつ説明してください。
```

```
#codebase このリポジトリの中で、変更依頼「CR-2026-012」が出てくるファイルをすべて挙げてください。
```

> 渡す資料が多いほど、クレジットを多く使い、答えもぼやけがちです。**必要な資料だけを渡す** のが基本です。

### 2. 監督モード（Supervised）に切り替える（5分）

Kiro には2つの進め方があります。

| モード | 動き方 |
|---|---|
| **Autopilot**（最初の設定） | Kiro がファイルの作成・修正を最後まで進める。終わってから変更をまとめて確かめる |
| **Supervised**（監督モード） | Kiro がファイルを直すたびに止まり、**変更を1か所ずつ確かめてから受け入れる** |

1. チャット欄の入力欄の近くにある **Autopilot** のスイッチを押して、オフ（Supervised）にする
   - スイッチが見つからないときは、`Ctrl` + `,` で設定を開き、`Agent Autonomy` を検索して **Supervised** を選ぶ

### 3. Kiro に文書を作らせ、直した箇所を確かめる（15分）

1. 新しいセッションを開き、次を送る（`taro` は自分の名前に）

   ```
   #materials/ベンダー依頼文_下書き_サンプル.md をもとに、ベンダーに送れる形に清書した文書を
   participants/taro/ベンダー依頼文_清書.md として作ってください。
   下書きに書かれていない情報は補わず、あいまいな点は【要確認】と書いて残してください。
   ```

2. Kiro が止まり、作ろうとしている内容が表示されます。読んで、よければ **Accept（受け入れる）** を押す
3. 続けて、次を送る

   ```
   清書の中の【要確認】の箇所を、文書の最後に「確認したいこと」という見出しで箇条書きにまとめ直してください。
   ```

4. 今度は、変更された箇所が **緑（追加）と赤（削除）** で表示されます
   - 変更のまとまり（ハンク）ごとに、受け入れるか戻すかを選べます
   - 1か所は **Reject（戻す）** を押してみて、その部分だけ元のままになることを確かめる
   - 残りは **Accept** を押す。まとめて受け入れるときは **Accept All**、まとめて戻すときは **Reject All**

> 監督モードは、**AI に任せきりにせず、人が1か所ずつ判断する** 進め方です。大事な文書を直させるときに向いています。

### 4. やり直す：チェックポイントの Restore（15分）

1. **Autopilot** のスイッチをオンに戻す
2. わざと失敗させます。次を送る

   ```
   participants/taro/ベンダー依頼文_清書.md を、3行の箇条書きに縮めて上書きしてください。
   ```

   - Kiro が「本当に上書きしてよいか」と確認してきたら、「はい、上書きしてください」と答える

3. 清書が3行に縮まったのを確かめたら、チャットの履歴で **いま送った依頼のすぐ上** にある **Checkpoint** の行の **Restore** を押す
   - 清書が元に戻り、チャットの会話もその依頼を送る前まで巻き戻ります
4. 次に、2回続けて依頼します

   ```
   清書の最後に、問い合わせ先の欄を足してください。名前と連絡先は「（架空）」と書いてください。
   ```

   ```
   清書の冒頭に、短いあいさつ文を足してください。
   ```

5. チャットの履歴をさかのぼり、**1つ目の依頼（問い合わせ先）のすぐ上** にある **Checkpoint** の行の **Restore** を押す
   - 2回分の変更がまとめて戻り、チャットの会話もその時点まで巻き戻ります

| どの Restore を押すか | 戻る範囲 |
|---|---|
| **直前の依頼** のすぐ上 | その1回の依頼で変わったファイルと会話 |
| **もっと前の依頼** のすぐ上 | その時点より後の、すべての依頼で変わったファイルと会話 |

> Kiro の版によっては、返答のあと入力欄の上に **Revert** が出ることがあります（直前の1回分のファイルだけを戻し、会話は残すボタン）。出ない版でも、Restore を使えば同じように戻せます。

> **戻らないものもあります。** 自分で手で直した部分や、Kiro がコマンドを実行して変えたもの（コミット・プッシュなど）は、チェックポイントの Restore では戻りません。
> 迷ったら、**コミットする前に** 確かめるのが一番安全です。

### 5. コミット・プッシュを Kiro に頼む（10分）

できた清書を保存（コミット）して、GitHub に送り（プッシュ）ます。

1. 次を送る

   ```
   participants/taro/ の変更を「ベンダー依頼文の清書を追加」というメッセージでコミットして、
   GitHub にプッシュしてください。
   ```

2. Kiro が `git add`・`git commit`・`git push` などのコマンドを実行しようとして、許可を求めてきます
   - 表示されたコマンドに `participants/自分の名前/` や自分のブランチ名が入っていることを確かめてから許可する
   - `main` に直接送るコマンドや、意味の分からないコマンドなら、**許可せずに止まって**、「このコマンドは何をするものですか」とチャットで聞く
   - 初めてプッシュするときは、GitHub へのサインインを求められることがあります。ブラウザが開いたら、自分の GitHub アカウントでサインインし、**Authorize（許可）** を押す（「Git Credential Manager」の画面が出たら **Sign in with your browser** を選ぶ）
3. ブラウザで自分の GitHub のリポジトリ（`https://github.com/＜自分のユーザー名＞/kiro-handson-practice`）を開き、上部に「practice/自分の名前 had recent pushes」のような黄色い帯が出ていれば送れています

> **この回はプルリクエストを出しません。** 黄色い帯の **「Compare & pull request」** は押さずに、ここで終わりです。送った変更は自分のブランチ（`practice/自分の名前`）にたまっていき、main には入りません。プルリクエストは STEP 6 で出します。

> コミット・プッシュは、この先の回でもすべて同じように Kiro に頼みます。

## できたかチェック

- [ ] `#folder` と `#codebase` を使って、資料を渡した
- [ ] 監督モードで、変更を1か所 Reject し、残りを Accept した
- [ ] Restore で、3行に縮めた文書を元に戻した
- [ ] チェックポイントの Restore で、2回分の変更をまとめて戻した
- [ ] Kiro に頼んでコミット・プッシュし、GitHub に自分のブランチが出た

## 困ったとき

- Autopilot のスイッチが見つからない → 設定（`Ctrl` + `,`）で `Agent Autonomy` を検索する
- Accept / Reject のボタンが出ない → Autopilot がオンのままです。手順2をやり直す
- Restore を押しても戻らない → 手で直した部分や、コマンドで変えたものは戻りません。「清書を、元の版に戻してください」と頼む
- ファイルが `participants/自分の名前/` 以外にできた → 「作ったファイルを participants/自分の名前/ に移動して」と頼む
- プッシュでサインインを何度も求められる → [困ったとき集](troubleshooting.md) の「GitHub にサインインできない」

> 画面の表記（ボタン名など）は、Kiro IDE のバージョンによって少し違うことがあります。見つからないときは、チャットで「○○のボタンが見つかりません。どこにありますか？」と聞くか、Kiro の公式ドキュメントで確認してください。
