# STEP 1 ログインと利用ルール（30分）

## この回の目的

- Kiro IDE と GitHub の両方にログインできる状態にする
- 「AIに入れてはいけない情報」を確認する

## 準備するもの

- [STEP 0 始める前の準備](00-environment.md) が終わっていること
  - Git・Kiro IDE がインストール済み
  - 自分の GitHub アカウントに、このリポジトリのコピー（`kiro-handson-practice`）がある

---

## 手順

### 1. Git が入っているか確認する（5分）

1. スタートメニューで「PowerShell」と入力して検索し、**Windows PowerShell** を開く
2. 次のコマンドを入力して Enter

```
git --version
```

3. `git version 2.xx.x` のようにバージョンが出れば OK。「認識されません」と出たら、[STEP 0](00-environment.md) の「2. Git をインストールする」に戻る

> `git bash` のように打つと「is not a git command」と出ますが、これは Git は入っているという意味です。確認に使うコマンドは `git --version` です。
> Mac の人は「ターミナル」を開き、同じく `git --version` と入力して Enter。

### 2. Kiro IDE を起動してログインする（10分）

1. Kiro IDE を起動する
2. 「Choose a way to sign in/sign up」の一覧から、使いたい方法を1つ選ぶ

   | 選択肢 | こんな人に |
   |---|---|
   | **GitHub** | GitHub のアカウントでそのまま入りたい人（このハンズオンでおすすめ） |
   | **Google** | Google のアカウントで入りたい人 |
   | **AWS Builder ID** | AWS Builder ID を持っている、または作りたい人 |

   - **Your organization** は、組織でまとめて用意した Kiro を使う人向けです。このハンズオンでは選びません
3. ブラウザが開くので、選んだアカウントでサインインし、Kiro へのアクセスを **許可** する
   - 初めての人は、ここで Kiro のアカウントが作られます（無料プランから始まります）
4. 「Kiro に戻りますか？」のような表示が出たら、許可して Kiro の画面に戻る
5. 初回は、テーマ（色）や設定の取り込みなどを聞かれることがあります。好みで選ぶか、そのまま進めてかまいません
6. キーボードで **`Ctrl` + `L`** を押すと、右側にチャット欄が開きます。チャット欄が表示されればログイン完了です
   - 画面右上の **チャットの切り替えボタン** を押しても開きます
   - 左端に並ぶアイコンの中の **Kiro のおばけのアイコン** を押すと開くのは **Kiro パネル**（Specs・Agent Hooks・Agent Steering & Skills・MCP Servers の一覧）です。チャット欄とは別のものです

> **有料プランに申し込む場合：** STEP 1〜9 を通して行うなら、Pro プラン（2026年10月時点で月1,000クレジット）がおすすめです。申し込みは Kiro の画面のアカウントの表示や、Kiro の Web サイトのアカウントページから行えます。料金は [STEP 0](00-environment.md) の「4. Kiro のプランとクレジット」を見てください。

### 3. GitHub で自分のリポジトリを開く（5分）

1. ブラウザで `https://github.com/` を開き、自分のアカウントでサインインする
2. `https://github.com/＜自分のユーザー名＞/kiro-handson-practice` を開き、README（このハンズオンの説明）が表示されることを確認する
   - 画面左上に **自分のユーザー名 / kiro-handson-practice** と出ていれば、自分のコピーです

> 「404」や「見つかりません」と出たら、まだコピーができていないか、名前が違います。[STEP 0](00-environment.md) の「5. このリポジトリを自分の GitHub アカウントにコピーする」を確認してください。

### 4. 利用ルールを確認する（10分）

表を声に出して読み、「入れてはいけない情報」の具体例を3つ（例：お客さまの氏名、電話番号、問い合わせ内容の原文）メモに書き出してください。

| ルール | 理由 |
|---|---|
| 個人情報・顧客情報は入れない | AI に送った内容は、外部のサービスで処理されます。自分や他人の大切な情報を守るためです |
| 練習ではサンプル資料だけを使う | 慣れるまでは「入れてよいか」の判断を不要にするため |
| パスワード・API キーなどの秘密情報は入れない | 一度送った情報は取り消せません。エラー画面を貼るときも写り込みに注意します |
| 迷ったら入れない・許可しない | 判断に迷うものは入れないのが原則です |
| クレジットを意識する | 重いモデルほど早く減り、使い切ると翌月まで使えません |

**クレジットを節約するコツ**
- チャット欄の下にあるモデル選択は、手順書に指示がない限り **既定（Auto）のまま** にする
- 同じ質問を何度も投げ直すより、1回の依頼に「目的・前提・ほしい形」を書く（STEP 3 で練習します）
- 残りのクレジットは、Kiro の画面のアカウントの表示や、Kiro の Web サイトのアカウントページで確認できます。一度見ておきましょう
