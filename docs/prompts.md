# プロンプト集（コピーして使える頼み方）

`#ファイル名` の部分は、入力欄で `#` を打って候補からファイルを選んでください。

## 良い頼み方の型

```
（役割）あなたは＿＿＿のアシスタントです。
（資料）#＿＿＿ を読んで、
（ほしい形）＿＿＿の形で整理してください。
（守ってほしいこと）推測で補わず、資料に書いてあることだけを使ってください。
```

---

## 読む・まとめる

**要約**
```
#＿＿＿ を読んで、忙しい上司向けに3行で要約してください。
```

**決定事項と ToDo の整理**
```
#＿＿＿ を読んで、「決まったこと」「持ち越し」「ToDo（担当・期限の表）」に整理してください。
書かれていない項目は「未記載」としてください。
```

**分かりやすく説明させる**
```
#＿＿＿ の内容を、システムに詳しくない業務部門の人向けに説明してください。専門用語は使わないでください。
```

## 点検させる・質問させる

**抜けを質問させる**
```
#＿＿＿ を、＿＿＿（例：ベンダー）の立場で読んだとき、情報が足りない点・あいまいな点を、質問の形で重要な順に10個挙げてください。
```

**食い違いを探させる**
```
#＿＿＿ と #＿＿＿ を突き合わせて、内容が食い違っている点を表にしてください。
```

**要件の点検**
```
この requirements.md の中で、互いに矛盾している条件と、テストで合否を判定できないあいまいな書き方を指摘してください。
```

## Spec を進める

**要件を作る**
```
#＿＿＿ の依頼をもとに、要件を作ってください。受け入れ条件は EARS 記法で書いてください。
```

**AI にリードさせる**
```
この requirements.md に足りない観点や依頼者に確認すべき点を、質問の形で挙げてください。それぞれに「おすすめの答え」も付けてください。
```

**決められないことを残す**
```
今の質問のうち、依頼者に確認しないと決められないものは「未確定事項（確認先）」の節にまとめてください。
```

**量を絞る**
```
練習なので、要件は5個以内、タスクは5〜7個にまとめてください。
```

**分からないところを聞く**
```
design.md の「＿＿＿」の部分を、プログラムを知らない人向けに説明してください。
```

**不具合を伝える**
```
受け入れ条件「＿＿＿」を満たしていません。実際には＿＿＿になりました。直してください。
```

## スキル・MCP（STEP 9）

**スキルを呼び出す**
```
/minutes-summary #＿＿＿
```

**スキルを作らせる**
```
＿＿＿をするスキルを作ってください。場所は .kiro/skills/＿＿＿-自分の名前/SKILL.md です。
手順は＿＿＿、出力の形は＿＿＿にしてください。
```

**MCP の道具で調べさせる**
```
AWS の公式ドキュメントで調べて答えてください。＿＿＿？ 根拠になったページの URL も付けてください。
```

## AI-DLC ワークフロー（STEP 10）

> エージェントの選択が **aidlc** になっていることを確認してから送ります。

**設定を確認する**
```
/aidlc --doctor
```

**試作の型で始める**
```
/aidlc poc --learnings off ./vision.md と ./technical-environment.md を読んで、書かれているものを作ってください。質問・文書・画面の文言はすべて日本語でお願いします。
```

**今どこにいるかを見る**
```
/aidlc --status
```

**一時停止する／再開する**
```
/aidlc park
```
```
/aidlc --resume
```

**差し戻す（承認ゲートで）**
```
2 ＿＿＿ を ＿＿＿ に直してください
```

## GitHub の操作を頼む

**ブランチを作る（STEP 2）**
```
practice/＿＿＿ という名前のブランチを作って、そのブランチに切り替えてください。
```

**最新にする**
```
最新の状態を取り込んで（pull して）ください。
```

**コミットしてプッシュする（STEP 4 から毎回）**
```
今の変更を「＿＿＿」というメッセージでコミットして、プッシュしてください。
```

**今の状態を聞く**
```
今いるブランチと、まだコミットしていない変更を教えてください。
```

> Kiro がコマンドを実行する前には許可を求められます。何をしようとしているか読んでから許可しましょう。分からなければ「このコマンドは何をするものですか」と聞いて構いません。
