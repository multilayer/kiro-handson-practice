# ひとりで進めるときのガイド

このハンズオンは、**手順書を読みながらひとりで進める** ことを前提に作っています。
始める前に、このページをひととおり読んでください。

---

## 1. 始める前に

[STEP 0 始める前の準備](00-environment.md) で、次の4つがそろっていることを確かめます。

| 準備 | 確認方法 |
|---|---|
| Kiro IDE が入っていて、サインインできる | Kiro IDE を起動して、チャット欄（`Ctrl` + `L`）が開く |
| PC に Git が入っている | PowerShell で `git --version` と打つとバージョンが出る |
| GitHub のアカウントがある | `https://github.com/` にサインインできる |
| 自分のアカウントにハンズオン用リポジトリのコピーがある | `https://github.com/＜自分のユーザー名＞/kiro-handson-practice` が開ける |

---

## 2. 進め方

1. **STEP 1 から順に** 進める。前の回で作ったもの（ブランチ・ファイル）を次の回で使うので、飛ばさない
2. 手順書を左、Kiro を右に並べて、**1行ずつ画面と見比べながら** 操作する
3. 各回の最後の「できたかチェック」が全部できたら、次の回へ進む
4. 時間は手順書の目安の **1.5倍** くらいを見ておく。1回分を一度に終わらせなくてもかまいません
5. 手順書は、ブラウザで自分のリポジトリの `docs/` を開いて読むのがおすすめです（GitHub の画面では、Markdown が見やすく表示されます）

### 分からなくなったとき

1. まず [困ったとき集](troubleshooting.md) で同じ症状を探す
2. Kiro のチャットに、画面に出ているメッセージをそのまま貼って「これはどういう意味ですか？ 何をすればよいですか？」と聞く（**個人情報・顧客情報が写っていないことを確認してから**）
3. それでも分からなければ、Kiro や GitHub の公式ドキュメントで、画面に出ている英語のメッセージを検索する

> 「許可してよいか分からない」ときは、**許可せずに止まる** のが正解です。急ぐ必要はありません。

## 3. 人が必要な場面の進め方

ふつうは「隣の人」や「依頼者」が手伝う場面を、ひとりで進められるようにしてあります。

| 回 | 人と一緒なら | ひとりのとき（この手順書の基本） |
|---|---|---|
| STEP 1 | 利用ルールを読み合わせる | ルールの表を声に出して読み、「入れてはいけない情報」を3つ書き出す |
| STEP 3 | 答え合わせをし合う | 手順書の最後の「答え合わせ」を開いて確かめる |
| STEP 6 | 仲間が要件をレビューする | Kiro にレビュー役をさせる。完成見本とも見比べる |
| STEP 7 | 仲間が承認（Approve）する | 受け入れ条件のチェックを自分で終えてから、自分でマージする |
| STEP 8 | 集まってモブ演習をする | Kiro に依頼者役をさせ、自分がナビゲーターとドライバーを兼ねる |
| STEP 10 | ― | 手順書の「クレジットの目安」に従う |

> 仲間と一緒に進めたい場合は、[勉強会で使うときのガイド](study-group-guide.md) を見てください。

## 5. ひとりで進めるときの注意

- **個人情報・顧客情報は入れない。** 見ている人がいなくても、ルールは同じです
- **練習ではサンプル資料だけを使う。** 「自分の仕事の資料で試したい」と思っても、まずはサンプルで最後まで通す
- **パスワード・API キーなどの秘密情報は入れない。** エラーのメッセージを貼るときも、写り込んでいないか確かめる
- **モデルは Auto のまま。** STEP 10 以外でモデルを変えない
- **自分の `participants/自分の名前/` と `practice/自分の名前` ブランチで作業する。** 手順書の中の `taro` は、自分の名前（ローマ字）に読み替えてください
- **公開元のリポジトリではなく、自分のコピーで作業する。** プッシュやプルリクエストの宛先が `＜自分のユーザー名＞/kiro-handson-practice` になっているかを確かめる習慣をつけましょう
