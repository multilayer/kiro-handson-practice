# 業務説明：システム変更依頼の流れ（ハンズオン用サンプル）

> ハンズオン用の架空の業務説明です。

## この業務の概要

社内の業務部門から「システムをこう変えてほしい」という依頼（変更依頼）を受け付け、内容を整理して開発ベンダーに伝え、リリースまでの進み具合を管理する業務です。
システム企画チームは、**業務部門と開発ベンダーの間に立つ取りまとめ役** を担っています。

## 登場する人

| 立場 | 役割 |
|---|---|
| 業務部門（依頼者） | 変更してほしい内容と、いつまでに必要かを伝える |
| システム企画チーム（取りまとめ役） | 依頼を受け付け、内容を整理し、ベンダーに依頼する。進み具合を管理し、定例で報告する |
| 開発ベンダー | 見積もり・開発・テストを行い、リリースする |

## 流れ

1. **受付**：業務部門から依頼メールを受け取り、変更依頼一覧に登録する（依頼IDを振る）
2. **見積中**：内容を整理してベンダーに見積もりを依頼する。不明点は業務部門に確認する
3. **開発中**：見積もりの承認後、ベンダーが開発する
4. **テスト中**：ベンダーのテストと、業務部門の受け入れ確認を行う
5. **完了**：リリースされたら完了にする

途中で依頼がなくなった場合は **取り下げ** にする。

## 変更依頼一覧の項目

| 項目 | 説明 |
|---|---|
| 依頼ID | `CR-年-連番` の形式 |
| 件名 | 依頼の内容を一言で |
| 依頼部署 | 依頼してきた業務部門 |
| 依頼日 | 依頼を受け付けた日 |
| 希望リリース日 | 業務部門が希望する、リリースの期限 |
| 優先度 | 高／中／低 |
| ステータス | 受付／見積中／開発中／テスト中／完了／取り下げ |
| 担当ベンダー | 依頼先のベンダー |
| 概算工数(人日) | ベンダーの見積もり。見積もり前は空欄 |

## 困っていること

- 変更依頼一覧は Excel で管理しているが、件数が増えて **期限が近いもの・過ぎているもの** が分かりにくい
- 定例のたびに、ステータスごとの件数を手で数えて報告している
- 議事録で決まったことが、一覧表に反映されないことがある
